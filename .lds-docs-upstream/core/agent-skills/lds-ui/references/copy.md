# 한국어 UI 카피 규칙

정본: `@lk-design-system/lds-core/docs/foundations/writing.md`, `foundations/voice-and-tone.md`, `docs/policies/COPY_REVIEW_CONTRACT.md`. 여기는 조립 시점에 적용할 결정 규칙 요약이다.

## 원칙

- **정확성은 친근함보다 우선한다.** 부드럽게 말하려고 사실을 흐리지 않는다.
- **좋은 원문은 건드리지 않는다.** 자연스럽고 기준을 만족하는 기존 문구를 "개선"하려고 바꾸지 않는다.

## 문형 규칙

| 대상 | 규칙 | 예 |
|---|---|---|
| 에러 메시지 | 원인 1문장 + 다음 행동 1문장 | "서버와 연결이 끊어졌습니다. 네트워크를 확인한 뒤 다시 연결해 주세요." |
| 버튼 | 구체 동사. **확인/처리 금지** | 저장, 다시 연결, 삭제 — ("확인" ✗) |
| 마침표 | 완전한 문장에만. 레이블·제목·버튼에는 없음 | |
| 말줄임 | `…` 한 글자. `...` 금지 | |
| 파괴적 동작 | 대상·결과·외부 영향·복구 가능성 명시 | "지도 3개가 삭제되며 복구할 수 없습니다" |
| 결측값 | `—`. 0을 지어내지 않는다 | |
| 날짜 | ISO 형식 | 2026-08-16 |

## 상태 동사의 구분 — ACK는 완료가 아니다

`sent(보냄) · accepted(접수됨) · applied(적용됨) · confirmed(확인됨)`는 서로 다른 사실이다. 요청이 전송 성공했다고 "완료"라고 쓰지 않는다. 특히 명령형 UI(정지 요청, 설정 적용)에서: 요청 중 → 접수됨 → 실제 완료를 각각 다른 문구로 구분한다.

## 노출 금지

- **원시 enum·코드값을 사용자에게 노출하지 않는다** (`IDLE`, `ERR_TIMEOUT` ✗ → 대기 중, 응답 시간 초과).
- 고유명사·숫자·단위는 보호 대상이다 — 번역·의역하면서 바꾸지 않는다.

## 단위 결합

`%`, `‰`, `°`만 값에 붙이고 **나머지 단위(℃ 포함)는 띄어 쓴다**. 직접 이어붙이지 말고 컴포넌트의 `unit` prop 또는 공유 포매터를 쓴다.

## 제목 형태 (문서·슬라이드·섹션 헤딩)

- 주장형 제목은 **명사형 종결**: "복구 시간 절반 단축" (✓) / "복구 시간이 절반으로 줄었다" (✗ — 문장은 governing/본문의 것).
- 완전한 문장이 필요한 자리(인용, statement)는 반대로 문장이어야 한다.

## 카피 리뷰 단위

카피를 검토할 때는 문자열 하나가 아니라 **세트**(제목 + 설명 + 버튼 + 진행 + 에러)로 본다. 권위 순서: 제품 실제 동작 > 정식 명칭 > LDS Writing/Voice > 현재 문구 > AI 제안. 세트 안에 의미가 불확실한 항목이 하나라도 있으면 세트 전체를 보류한다.
